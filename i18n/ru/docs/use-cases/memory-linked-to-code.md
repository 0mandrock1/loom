# Память, связанная с кодом, для кодирующих агентов

Loom связывает каждую память, которую сохраняет кодирующий агент, с функциями, классами и файлами, которые в ней названы, отслеживает эти символы при рефакторингах и помечает память, когда этот код меняется.
По умолчанию память, весь код которой исчез, исключается из поиска, так что устаревшие уроки перестают попадать к агентам. Функция работает на репозиториях, которые индексирует Loom ([индекс кода](code-intelligence.md), `LOOM_CODE_INGEST_ENABLED=true`), а воркер `memory_code_links`, поддерживающий связи, включён по умолчанию.

<a id="what-you-get"></a>

## Что вы получаете

- **Уроки, привязанные к коду, о котором они.** Память, помеченная тегом репозитория (плагины Claude Code и Codex помечают так свои сессии) или записанная в пространство имён кода репозитория, связывается с каждым определением, названным в ней в обратных кавычках и однозначно разрешающимся в одно место (а внутри перечисленных в ней файлов также с определениями, названными просто словом), и с каждым названным в ней файлом, в котором таких определений нет. Квалифицированное имя, которого ещё нет в основной ветке, связывается, если оно попадает в неё в течение `memory_code_links_pending_days` (14).
  [Память, связанная с кодом](https://github.com/ClickHouse/loom/blob/main/docs/concepts/memory.md#memories-linked-to-code)
- **Связи, которые следуют за рефакторингами.** На каждом проиндексированном коммите каждая связь получает состояние `fresh`, `moved`, `changed` (с указанием коммита, который её изменил), `unresolved` или `missing`. Связь запоминает токены определения, поэтому пробелы, комментарии и большинство изменений форматтера оставляют её в состоянии `fresh`.
- **Устаревшая память обрабатывается так, как вы выбрали.** Параметр `code_change_policy` пространства имён либо исключает из поиска память, весь код которой исчез (`retire_removed`, по умолчанию), либо только помечает её (`flag`), либо поручает модели сверить утверждение со старым и новым кодом и предложить исправленное (`revise`). Сам Loom саму память никогда не переписывает.
- **Уроки появляются там, где агент читает код.** `code.symbol` возвращает память, связанную с определением, как `lessons`, каждую со своим состоянием связи; `memory.for_file` отдаёт память, связанную с кодом в файле; плагин Claude Code показывает её перед правкой этого файла. [`code.symbol`](https://github.com/ClickHouse/loom/blob/main/docs/reference/operations/code.md#codesymbol) ·
  [плагин Claude Code](https://github.com/ClickHouse/loom/blob/main/docs/features/integrations/claude-code.md)
- **Ветки читают свой собственный код.** В релизной ветке, где ещё сохранился старый текст, урок остаётся в состоянии `fresh`, после того как основная ветка изменила его.
- **Документы рядом с кодом.** Документы из источника, зарегистрированного в пространстве имён кода основной ветки репозитория, получают тег репозитория, поэтому поиск по репозиторию читает их вместе с кодом (для воркера синхронизации нужен `LOOM_KNOWLEDGE_SOURCE_SYNC_ENABLED`).
  [Источники документов](https://github.com/ClickHouse/loom/blob/main/docs/features/knowledge.md#document-sources)
- **Список для проверки.** `namespace.validate` перечисляет память, код которой изменился или исчез, а панель управления показывает связи каждой памяти и их состояние.

<a id="start"></a>

## Начало работы

[Быстрый старт](../getting-started/quickstart.md) запускает Loom, а
[добавление репозиториев](https://github.com/ClickHouse/loom/blob/main/docs/features/code-index/repositories.md) включает индекс кода для
репозитория. Подключите своего кодирующего агента через плагин или по MCP
([подключение кодирующего агента](https://github.com/ClickHouse/loom/blob/main/docs/getting-started/connect-a-coding-agent.md)) и сохраните урок,
в котором определение названо в обратных кавычках. Когда основная ветка проиндексирована и прошёл следующий проход связывания
(по умолчанию каждые 60 секунд), `code.symbol` для этого определения вернёт урок в `lessons`.
