# Память, связанная с кодом, для агентов программирования

Loom связывает память агентов программирования с функциями, классами и файлами, которые они называют, прослеживает их через рефакторинги и помечает память, когда её код меняется. По умолчанию поиск не возвращает память, весь код которой исчез, если только человек не закрепил, не заблокировал или не подтвердил её, а каждое чтение, выдающее урок, сообщает, когда его код изменился или исчез. Это работает через MCP, HTTP и SDK на репозиториях, которые индексирует самостоятельно развёрнутый Loom ([индекс кода](code-intelligence.md), `LOOM_CODE_INGEST_ENABLED=true`), а воркер `memory_code_links`, который поддерживает связи, включён по умолчанию.

<a id="what-you-get"></a>

## Что вы получаете

- **Уроки, привязанные к коду, о котором они.** Память с тегом `repo:<id>` (плагины Claude Code и Codex ставят этот тег на то, что фиксируют их хуки) или записанная в пространстве имён кода репозитория связывается с каждым определением (функцией, классом или другим символом), которое она называет в обратных кавычках, либо в любом месте текста как `A::b` или вызов (`a.b()`, `name()`) и которое однозначно разрешается в одно место (для неквалифицированного имени нужно четыре символа или больше); с определениями в перечисленных в ней файлах, которые она называет простым словом в camelCase или snake_case; и с каждым перечисленным в ней файлом, в котором нет ни одного из них. Квалифицированное имя, которого ещё нет в основной ветке, связывается, если оно попадает туда в течение `LOOM_MEMORY_CODE_LINKS_PENDING_DAYS` (14 дней).
  [Память, связанная с кодом](https://github.com/ClickHouse/loom/blob/main/docs/concepts/memory.md#memories-linked-to-code)
- **Связи, которые следуют за рефакторингами.** На каждом проиндексированном коммите каждая связь получает состояние `fresh`, `moved`, `changed` (с указанием коммита, который её изменил), `unresolved` или `missing`. Связь запоминает токены определения, поэтому пробелы, комментарии и большинство изменений форматтера оставляют её в состоянии `fresh`. [Состояния связей](https://github.com/ClickHouse/loom/blob/main/docs/concepts/memory.md#memories-linked-to-code)
- **Устаревшая память обрабатывается так, как вы выберете.** Это решает [`code_change_policy`](https://github.com/ClickHouse/loom/blob/main/docs/reference/operations/namespace.md#namespaceregister) пространства имён: `retire_removed` (по умолчанию) убирает из поиска память, весь код которой исчез, и помечает изменённый код; `flag` только помечает; `revise` тоже убирает из поиска память с исчезнувшим кодом и поручает модели сверить утверждение изменённой памяти со старым и новым кодом: утверждение, которое остаётся верным, заново привязывается, а опровергнутое получает предложенное исправление. Память, которую человек закрепил, заблокировал или подтвердил, из поиска не убирается никогда. При любой политике поиск обычно ранжирует память с изменённым кодом ниже следующих трёх результатов, а не скрывает её; удерживаемая память и строка, найденная по имени, сохраняют своё место. Саму память Loom никогда не переписывает.
  [Политики](https://github.com/ClickHouse/loom/blob/main/docs/concepts/memory.md#memories-linked-to-code)
- **Уроки везде, где агент читает код.** `code.symbol` возвращает память, связанную с определением, как `lessons`; `code.search`, `code.callers`, `code.callees`, `code.impact`, `code.outline` и `code.context_pack` задачи прикрепляют уроки для файлов, которые возвращают; каждый урок содержит состояние своей связи. Хуки Claude Code и Codex показывают память файла (`memory.for_file`) до того, как агент его изменит, а хуки Cline — когда он читает или изменяет файл. [`code.symbol`](https://github.com/ClickHouse/loom/blob/main/docs/reference/operations/code.md#codesymbol) · [плагин Claude Code](https://github.com/ClickHouse/loom/blob/main/docs/features/integrations/claude-code.md) · [плагин Codex](https://github.com/ClickHouse/loom/blob/main/docs/features/integrations/codex.md) · [хуки Cline](https://github.com/ClickHouse/loom/blob/main/integrations/cline/README.md) (экспериментально)
- **Общий доступ для команды.** Уроки читаются из пространства имён кода репозитория и пространств имён, которые называет вызов (по MCP по умолчанию — собственного пространства вызывающего), поэтому урок, сохранённый в пространстве имён кода репозитория, доступен каждому агенту, которому разрешено читать это пространство имён (токен, суженный до собственного пользователя или сессии, уроков не читает).
  [Память, связанная с кодом](https://github.com/ClickHouse/loom/blob/main/docs/concepts/memory.md#memories-linked-to-code)
- **Ветки читают собственный код.** В другой ветке урок сверяется с определением из этой же ветки, поэтому релизная ветка, в которой остался старый текст, показывает `fresh`.
  [Память, связанная с кодом](https://github.com/ClickHouse/loom/blob/main/docs/concepts/memory.md#memories-linked-to-code)
- **Документы рядом с кодом.** Документы из источника, зарегистрированного в пространстве имён кода репозитория (его основной ветки), получают тег репозитория, поэтому поиск по репозиторию читает их вместе с его кодом (для воркера синхронизации нужен `LOOM_KNOWLEDGE_SOURCE_SYNC_ENABLED`).
  [Источники документов](https://github.com/ClickHouse/loom/blob/main/docs/features/knowledge.md#document-sources)
- **Список для проверки.** [`namespace.validate`](https://github.com/ClickHouse/loom/blob/main/docs/reference/operations/namespace.md#namespacevalidate) перечисляет память, код которой изменился, не был найден снова или исчез, а панель управления показывает связи каждой памяти и их состояние.

## Начало работы

[Быстрый старт](../getting-started/quickstart.md) запускает Loom, а [добавление репозиториев](https://github.com/ClickHouse/loom/blob/main/docs/features/code-index/repositories.md) включает индекс кода для репозитория. Подключите своего агента программирования через его плагин или по MCP ([подключение агента программирования](https://github.com/ClickHouse/loom/blob/main/docs/getting-started/connect-a-coding-agent.md)). Сохраните урок, который называет определение из четырёх или более символов в обратных кавычках или как вызов (`` `name()` ``), либо квалифицированное имя, например `` `Reader.run` ``. Плагины Claude Code и Codex ставят на то, что фиксируют их хуки, тег `repo:<id>`, а праймер сессии называет этот id ([как он выводится](https://github.com/ClickHouse/loom/blob/main/docs/features/integrations/claude-code.md#configuration)). Урок, который агент сохраняет сам через `loom_memory_set`, связывается, если несёт этот тег (`tags: ["repo:<id>"]`) или записан в пространстве имён кода репозитория; любой клиент может сделать и то и другое. По HTTP (или через `agent.call` в Python SDK) урок, сохранённый в вашем собственном пространстве имён, читается, только если вызов называет это пространство имён в `lesson_namespaces`. Каждый проход связывания обрабатывает записи возрастом не менее 60 секунд, а проходы выполняются каждые 60 секунд, поэтому после индексации основной ветки `code.symbol` для этого определения возвращает урок в `lessons` примерно за две минуты.

Некоторые операции на этой странице отмечены как экспериментальные на [странице статуса](https://github.com/ClickHouse/loom/blob/main/docs/reference/status.md).
