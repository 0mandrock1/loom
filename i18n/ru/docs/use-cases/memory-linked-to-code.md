# Память, связанная с кодом, для агентов программирования

Loom связывает воспоминания, которые агенты программирования сохраняют о репозитории, с функциями, классами и файлами, которые в них названы, прослеживает эти символы через рефакторинги и помечает память, когда её код меняется. По умолчанию память, весь код которой исчез, пропадает из поиска, поэтому устаревшие уроки перестают попадать к агентам. Функция работает на репозиториях, которые индексирует Loom ([индекс кода](code-intelligence.md), `LOOM_CODE_INGEST_ENABLED=true`), а воркер `memory_code_links`, поддерживающий связи, включён по умолчанию.

<a id="what-you-get"></a>

## Что вы получаете

- **Уроки, привязанные к коду, о котором они.** Память с тегом `repo:<id>` (плагины Claude Code и Codex ставят этот тег на то, что фиксируют их хуки) или записанная в пространстве имён кода репозитория связывается с каждым определением, названным в ней в обратных кавычках и разрешающимся ровно в одно место; с определениями в перечисленных в ней файлах, названными голым словом в camelCase или snake_case; и с каждым названным файлом, в котором нет ни одного из них. Полное имя, которого ещё нет в основной ветке, связывается, если оно попадает в неё в течение `memory_code_links_pending_days` (14).
  [Воспоминания, связанные с кодом](https://github.com/ClickHouse/loom/blob/main/docs/concepts/memory.md#memories-linked-to-code)
- **Связи, которые следуют за рефакторингами.** На каждом проиндексированном коммите каждая связь получает состояние `fresh`, `moved`, `changed` (с указанием коммита, изменившего код), `unresolved` или `missing`. Связь запоминает токены определения, поэтому пробелы, комментарии и большинство изменений форматтера оставляют её в состоянии `fresh`.
- **Устаревшая память обрабатывается так, как выберете вы.** Решает [`code_change_policy`](https://github.com/ClickHouse/loom/blob/main/docs/reference/operations/namespace.md) пространства имён: `retire_removed` (по умолчанию) убирает из поиска память, весь код которой исчез, и помечает изменённый код; `flag` только помечает; `revise` тоже убирает память с исчезнувшим кодом, а для изменённой просит модель сверить утверждение памяти со старым и новым кодом и предложить исправленное утверждение. При любой политике поиск ранжирует память с изменённым кодом ниже следующих трёх результатов, а не скрывает её. Саму память Loom никогда не переписывает.
- **Уроки везде, где агент читает код.** `code.symbol` возвращает воспоминания, связанные с определением, как `lessons`; `code.search`, `code.callers`, `code.callees`, `code.impact`, `code.outline` и `code.context_pack` прикрепляют уроки для файлов, которые возвращают; каждый урок несёт состояние своей связи. Хуки Claude Code и Codex показывают память о файле (`memory.for_file`) до того, как агент его изменит, а хуки Cline делают это, когда агент читает или изменяет файл.
  [`code.symbol`](https://github.com/ClickHouse/loom/blob/main/docs/reference/operations/code.md#codesymbol) ·
  [плагин Claude Code](https://github.com/ClickHouse/loom/blob/main/docs/features/integrations/claude-code.md)
- **Общий доступ для команды.** Уроки читаются из командного пространства имён репозитория и, по умолчанию, из собственного пространства вызывающего, поэтому урок, сохранённый там одним агентом, доходит до каждого агента, читающего этот код.
- **Ветки читают свой код.** В другой ветке урок проверяется по определению из этой ветки, поэтому релизная ветка, где остался старый текст, получает состояние `fresh`.
- **Документы рядом с кодом.** Документы из источника, зарегистрированного в пространстве имён кода основной ветки репозитория, несут тег репозитория, поэтому поиски по репозиторию читают их вместе с кодом (для воркера синхронизации нужен `LOOM_KNOWLEDGE_SOURCE_SYNC_ENABLED`).
  [Источники документов](https://github.com/ClickHouse/loom/blob/main/docs/features/knowledge.md#document-sources)
- **Список для проверки.** [`namespace.validate`](https://github.com/ClickHouse/loom/blob/main/docs/reference/operations/namespace.md#namespacevalidate) перечисляет воспоминания, чей код изменился или исчез, а панель управления показывает связи каждой памяти и их состояние.

## Начало работы

[Краткое руководство](../getting-started/quickstart.md) запускает Loom, а [добавление репозиториев](https://github.com/ClickHouse/loom/blob/main/docs/features/code-index/repositories.md) включает индекс кода для репозитория. Подключите своего агента программирования через его плагин или по MCP ([подключение агента программирования](https://github.com/ClickHouse/loom/blob/main/docs/getting-started/connect-a-coding-agent.md)). Сохраните урок, в котором в обратных кавычках названо определение из четырёх или более символов (или полное имя, например `` `Reader.run` ``), с тегом `repo:<id>` или в пространстве имён кода репозитория. Когда основная ветка проиндексирована и через минуту после сохранения прошёл проход связывания (проходы запускаются каждые 60 секунд и отстают на 60 секунд от самой новой записи, то есть примерно за две минуты), `code.symbol` для этого определения вернёт урок в `lessons`.
